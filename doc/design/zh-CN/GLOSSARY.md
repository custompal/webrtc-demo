## 3. 语言切换器（冻结格式）

### 3.1 位置

切换器必须位于文件**前 8 行内**、**独立成行**（该行除切换器本身不得有其他内容），推荐放在第 1 行——本文件即放在第 1 行。切换器行不得写在代码块、表格或 HTML 注释里。

### 3.2 中文默认页（中文正文页、导读、原创规范、中文入口/索引）

严格格式：一个 `>`，后接加粗的「中文（默认）」，后接 ` · `，后接指向英文对应文件的链接（链接文本为 `English`）。

可直接复制的中文译文页示例（05 篇，链接在 [05-protocols.md](../05-protocols.md) 上可达）：

> **中文（默认）** · [English](../05-protocols.md)

各页的链接目标（相对路径，相对该中文页自身所在目录）：

| 中文页 | 链接目标 |
|---|---|
| `zh-CN/NN-<name>.md`（01–05） | 上一级目录（两点加斜杠的上级前缀）下的英文同名文件；逐字节示例见上方 05 篇的那一行 |
| 根 `README.md` | 同目录的 `README.en.md` |
| `doc/design/README.md` | 同目录的 `README.en.md` |
| `zh-CN/` 下的 `GLOSSARY.md` 与 `SPEC-guide.md` | 上一级目录的 `SPEC.md`（英文唯一规范） |

### 3.3 英文页

严格格式：一个 `>`，后接指向中文对应页的链接（链接文本为「中文（默认）」），后接 ` · `，后接 `English`。

模板（务必读下方警告）：

```text
> [中文（默认）]（zh-CN/NN-<name>.md） · English
```

**模板警告。** 上面这行模板为了**让本规范自身通过链接门禁**而故意使用全角圆括号（门禁会解析「右方括号紧跟半角左圆括号」的序列并校验链接可达性）。实际文件**必须**用半角括号书写；写成全角括号的页面其链接不可渲染、不可达，门禁直接 FAIL。

一个可达的 canonical 根形式示例（从仓库根写完整路径；门禁解析相对链接时会回退到仓库根，故该形式同样可达）：`> [中文（默认）](doc/design/zh-CN/GLOSSARY.md) · English`。

链接目标（相对路径，相对该英文页自身所在目录）：英文正文页指向 `zh-CN/` 目录下与其同名的中文页；两份 `README.en.md` 指向同目录的 `README.md`。

### 3.4 双向校验范围（配对清单，唯一）

双向校验**只覆盖**下面三组配对；配对任一侧缺失、切换器缺失或链接不可达即 FAIL：

| 中文默认页 | 英文页 |
|---|---|
| 根 `README.md` | 根 `README.en.md` |
| `doc/design/README.md` | `doc/design/` 下的 `README.en.md` |
| `zh-CN/NN-<name>.md`（NN = 01–05） | `doc/design/NN-<name>.md` |

* **S1** — 配对中的中文页前 8 行内必须存在切换器行，且其链接目标在磁盘上存在。
* **S2** — 配对中的英文页前 8 行内必须存在切换器行，且其链接目标在磁盘上存在。
* **S3** — 任一侧缺失、目标不存在或指向错误文件（例如 05 的译文指到 04 的英文页），门禁报 FAIL 并给出精确文件与行号，修复提示为「补上切换器行或修正链接目标」。
* **S4** — **豁免**：`zh-CN/` 下的 `GLOSSARY.md`、`zh-CN/` 下的 `SPEC-guide.md` 以及任何无英文对应物的文件**不参与**双向校验；其中 `SPEC-guide.md` 仍需要 §4 的译文声明，`GLOSSARY.md` 不需要。
* **S5** — 未翻译的英文页（06–11）本次不加切换器，也不列入校验；它们被标注为「待翻译（planned）」。

### 4.1 SPEC 不翻译的边界与理由

**边界。** 英文 [SPEC.md](../SPEC.md) 保持英文、保持原位、保持唯一规范地位，本次**不产出**它的中文译文；中文侧只新增一篇导读 `zh-CN/` 下的 `SPEC-guide.md`（由 T5 产出）。导读覆盖 SPEC 的结构与读者最常用的规则：§2 目录约定与路径词表、§4 引用格式、§5 模板、§7 判定规则与 P1–P5、§8 变更控制、§9 交付门槛，并再次声明「英文 SPEC 为唯一规范，本导读仅供参考」。

**理由（三条，缺一不可）。**

1. **SPEC 是判据本体，不是描述。** 它的表格（V1–V13、A1–A13、P1–P5、T1–T6、R1–R11、C1–C9、E1–E7）直接对应门禁脚本的判定分支；译文会引入解释自由度，任何一处措辞偏移都可能让译者按错误判据写作，而门禁仍按英文原文失败。
2. **引用链必须稳定。** 门禁脚本头、任务契约、冻结清单、验证报告都用英文 SPEC 的章节号引用判据（例如 §7.1 P4、§7.2、§7.5）。若出现一份中文 SPEC，同一规则会有两个可引用位置，报告与任务输出将无法机器对照。
3. **SPEC 仍在演进。** 本次中文布局所需的 SPEC 修订（§8.2 五处）已随 SPEC v1.7.0 落地，但 SPEC 本身仍会继续演进。译文一旦落后于原文，就会与门禁静默分歧；导读只用「结构与规则映射」的粒度承载说明，落后时是信息缺失而非判据错误。

因此：任何中文页与英文 SPEC 冲突时，以英文 SPEC 为准；中文页不得声称自己具有规范效力（`GLOSSARY.md` 只是 SPEC 的**中文配套规范**，约束对象限定为中文页的语言与术语，不改变 SPEC 的任何判据）。

## 5. 翻译规则（冻结）

### 5.1 一律原样保留（不译）

下列内容必须与英文原文**逐字节一致**，不得翻译、转写、扩写或「顺手修正」：

1. **代码引用**：形如 `path/file.ext:LINE` 或 `path/file.ext:LINE-LINE` 的整串，行号照抄；禁止因中文排版变化而改行号，禁止拆分路径或改冒号两侧的空白。
2. **协议字段名与消息类型字符串**：`sdpMLineIndex`、`peerJoined`、`ROOM_NOT_FOUND` 等，保持代码大小写与拼写。
3. **日志事件名与日志键**：`encoder_fallback_decision`、`room_not_found_action=keep_call` 等。
4. **代码跨度（code span）**：类名、函数名、常量、Gradle 任务、flag、环境变量、JSON 键、Mermaid 图内标识符。
5. **命令与脚本名**：命令示例整行照抄（含参数顺序）。
6. **路径与文件名**：仓库相对路径、目录名、生成表格名一律不译。
7. **证据锚点**：`reports/NN-*.md` 的报告编号与小节号、commit hash、构建/发布日志路径、端口号、URL。
8. **产品与协议名**：ICE、DTLS、SRTP、SDP、STUN、TURN、coturn、VP9、WebSocket、P2P、libwebrtc（见 §6）。

判定口径：一个 token 是否为「代码跨度」以英文页是否有反引号为唯一判据——英文页反引号包住的，中文页必须反引号包住且内容不变。

### 5.2 数字、单位与标识符

* 数字保留半角阿拉伯数字；单位与数字之间保留英文页的空格写法（例：`90 s`、`63 s`、`30 kbps`、`33 472 645 B`），不写成「90秒」。
* 出现在代码标识符内的时长保留源码写法（例：`90s`、`8_000`、`-room-grace`）。
* 百分比、端口、版本号、枚举取值（`Open`、`FullCone`、`RELAY`）保持半角原样。
* 千分位空格的写法照抄英文页，不改成逗号或全角空格。

### 5.3 标点与全角/半角

* **中文行文**用全角标点：`， 。 ； ： 、 （） 「」 ——`；不得在中文句子中用半角逗号或半角句号。
* **代码、路径、命令、标识符、数字、单位**一律半角；紧跟代码的括号用半角圆括号。
* 中英混排时，中文与英文/数字之间不加多余空格（英文页原有的空格照抄）。
* 链接、图片、表格分隔符保持 markdown 原语法（半角）。
* 本规范 §3.3 的模板是唯一例外：为通过门禁而使用全角括号并已就地标注。

### 5.4 结构与对照

* 中文页的标题层级、小节编号（`## 1.`、`### 2.1`）与英文页一一对应；不得增删小节、不得合并或拆分段落。
* 表格行列与英文页一一对应，行序不变；表格内不得增删列。
* 中文页与英文页的 `path:LINE` 引用集合必须相同；英文页更新引用时，中文页在同一任务窗口内同步到相同值。
* Mermaid 代码块、代码块、表格的数量与顺序也须一致（便于 T6 机器抽样对照）。

### 5.5 状态词与专有标记

* 状态词写作「中文定译（英文原词）」，首次出现带英文原词，例：`已实现（implemented）`、`部分实现（partially implemented）`、`已知限制（known limitation）`、`未验证（unverified）`、`已否决（rejected）`、`已证伪（disproven）`。英文原词必须保留，供门禁与机器对照。
* 需求与验收标识（`FR-*`、`NFR-*`、`D-1`…）不译。
* 路径 scope 标记 `HOST`、`CONTAINER`、`DEVICE`、`REPO` 不译；`WORKSPACE` 与 `ARTIFACT` 是已退役标记，不得使用——违规写法是在行首写标记加冒号再跟一个路径，例如：NEGATIVE EXAMPLE `WORKSPACE: tmp/n1/x/app.log`（本行显式标注为反面示例，勿照抄）。
* 未翻译篇章在中文索引中标注「待翻译（planned）」，不视为缺陷。

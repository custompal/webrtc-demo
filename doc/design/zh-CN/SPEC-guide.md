## 1. 这份导读是什么

[SPEC.md](../SPEC.md) 是唯一规范（normative）。本导读**不翻译**它，只给「结构与规则映射」：每条规则在哪一节、写文档时先看哪些条、门禁怎么判。任何冲突以英文 SPEC 为准；导读落后于 SPEC 时属于信息缺失，不构成判据。

为什么 SPEC 不翻译：它是门禁判据本体（表格直接对应检查分支）；报告、任务与冻结清单都用它的章节号引用判据；而且它仍在演进。三条理由详见 [GLOSSARY.md](GLOSSARY.md) §4.1。

## 3. §2 目录约定（最常用）

* 规范文档在 `doc/design/` 下；`docs` 是指向 `doc/design` 的兼容符号链接，中文页经 `docs/zh-CN/` 同样可达。
* 中文页放在 `zh-CN/` 子目录，文件名与英文页镜像同名（例：`05-protocols.md` 与 `zh-CN/` 下的 `05-protocols.md`）。
* 入口与索引成对：根 `README.md`（中文默认）与根 `README.en.md`（英文原文）；索引同理（`doc/design/` 下的 `README.md` 与 `README.en.md`）。不创建任何语言后缀副本：`README.zh-CN.md` 与 `zh-CN/` 下的 `README.md` 都不存在。
* `doc/*.md` 与 `doc/adr/*.md` 是历史 stub（恰好一行），归档在 `doc/archive/`；生成表格在 `doc/design/_generated/` 下，禁止手改。
* 目录或命名变更必须与 SPEC 更新同批完成（R8）；SPEC 自身变更需要 architect（R7）。

### 3.1 路径词表 T1–T6（§2.3）

scope token 只有四个：`HOST`、`CONTAINER`、`DEVICE`、`REPO`（默认）。`WORKSPACE` 与 `ARTIFACT` 是退役标记，写成行首前缀即违规。违规示例（本行显式标为反面示例）：NEGATIVE EXAMPLE `WORKSPACE: tmp/n1/x/app.log`

四种记法等价：行首前缀、行尾注释、代码块 info 字符串的 scope=、小节注释；优先级为行 > 代码块 > 小节 > 默认。

### 3.2 路径分类 P1–P5（§7.1）

| 级别 | 路径形状 | 判定 | 失败消息 |
|---|---|---|---|
| P1 REPO | 仓库相对路径且未被 gitignore | 硬校验：存在且覆盖引用行 | `missing repo path` |
| P2 WORKSPACE | 两点加斜杠前缀或 `tmp/` 开头，或名为 `env.sh`、`env-container.sh`、`env-go.sh` | 相对 workspace 根硬校验 | `missing workspace path` |
| P3 HOST | `opt`、`etc`、`var`、`home`、`root`、`usr`、`srv`、`tmp` 下的绝对路径 | 不校验存在性，但必须处于 HOST 或 DEVICE scope | `unmarked host path` |
| P4 CONTAINER | 容器根下的绝对路径 | 相对真实容器根硬校验 | `missing container path` |
| P5 ARTIFACT | 仓库相对但被 gitignore | 存在性可选，缺失永不失败 | 写退役前缀才算失败 |

## 4. §4 引用格式

* C1：代码引用写成 path 冒号行号（单行或 `LINE-LINE` 区间）；文件必须存在，且行数足够。
* C2：代码文件名不能裸写，除非同一表格或列表里已有带行号的引用。
* C3：类名、函数名、常量用反引号写源码拼写，且能在被引文件里逐字搜到。
* C4：协议消息类型、错误码、字段名照抄代码，不得发明类型。
* C5：日志事件名与字段键照抄；真机日志必须注明所在报告的编号。
* C6：每条实现陈述都要有证据：报告小节、commit、构建或发布日志，或显式的未验证标记。
* C7：文档之间的相对链接必须在磁盘上可达。
* C9：引用本 SPEC 一律用节号（例如 §7.1），不要写成 SPEC 文件名加行号。

## 5. §5 文档模板

英文页：标题行 + 页头块（Status、Owner、Task、Evidence base、Doc standard），随后按顺序是 Scope、Body、Evidence index、Open items。

中文页的语言切换器位于文件**前 8 行内**、独立成行（推荐第 1 行）；`zh-CN/` 下的 01–05 与本文件另在切换器之后写译文声明。两行的逐字节格式、配对清单与豁免清单见 [GLOSSARY.md](GLOSSARY.md) §3 与 §4。

## 6. §7 判定规则速查

| 规则 | 检查什么 | 失败消息 |
|---|---|---|
| V1 | 每条带行号的引用：文件存在、不是目录、行号在范围内 | 指向代码的断链 |
| V2 | 反引号符号能在同小节被引文件里逐字搜到 | 符号不存在或已改名 |
| V3 | 协议消息类型与生成表格一致 | 协议集合分歧 |
| V4 | 相对链接可达 | 悬空交叉引用 |
| V5 | 历史 stub 恰好一行且指向归档中存在的文件 | 历史引用悬空 |
| V6 | `docs` 是指向 `doc/design` 的符号链接；生成表格带 GENERATED 头 | 约定被破坏 |
| V7 | Gradle 任务名与构建或发布 flag 与真实字面量一致 | 不存在的命令或 flag |
| V8 | scope 记法合法；退役标记违规 | `retired marker` |
| V9–V13 | P1–P5 五类路径判定 | 见 §3.2 表 |
| V14 | 配对文件前 8 行内的语言切换器可达 | `missing language switcher` |
| V15 | 声明清单上的中文页逐字出现译文声明 | `missing translation disclaimer` |

A 规则里最常踩的几条：A1（只校验白名单扩展名的引用）、A5（本任务的门禁形式是加参数只跑自己的文件）、A8（scope 记法）、A10（P5 路径缺失只是 warning）、A13（行号按当前 HEAD 校验，不要复用报告里的行号）。

## 7. §8 变更控制与 §9 交付门槛

变更控制：R6 只改自己 inScope 的文件；R7 SPEC 变更需要 architect；R8 目录或命名变更与 SPEC 更新同批；R9 旧文件整体归档并留一行 stub；R10 文档任务不改源码、不跑 Gradle、不提交；R11 只有显式标注 NEGATIVE EXAMPLE 的行才豁免退役标记检查。

交付门槛（§9）：本任务文件子集门禁退出码为 0；每条实现陈述都有引用；英文页用英文、中文页用中文；任务输出列出改动路径与门禁退出码。

## 8. 中文页的额外要求

中文页的写作规则不在 SPEC 里，而在 [GLOSSARY.md](GLOSSARY.md)：目录布局（§2）、语言切换器（§3）、译文声明（§4）、不译清单与标点约定（§5）、术语表（§6）。中文页提交前跑自己的子集门禁，期望 failures 为 0。
